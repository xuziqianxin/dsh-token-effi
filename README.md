# dsh-token-effi

DeepSeek Harness 插件：**按会话算效费比**——这笔会话花的钱，有多少变成了你要的东西。

回答两个问题：

- **效费比**：有效产出 vs 返工，各占多少钱、各占多少 token
- **钱花在哪**：输入侧六分量、缓存命中与漏点、输出分块

## 安装

```
Plugins → Add plugin → 选择本目录
```

或发布后从 npm 安装：

```bash
dsh plugin add dsh-token-effi
```

装完刷新页面，左侧导航会出现 **效费比洞察**，会话叶签会出现 **效费比**。

## 两个位置

| 位置 | 看什么 |
|---|---|
| 会话叶签「效费比」 | **只看当前打开的这个会话**，切会话自动跟随 |
| 左侧「效费比洞察」 | 一屏看范围内所有会话，点一行看明细 |

洞察页默认只算**最近 7 天有活动**的会话（活动时间取会话目录里最新文件的 mtime），
顶部可切 近 7 天 / 近 30 天 / 近 1 年 / 全部。

## 口径

- **ET（等效 token）**：`未命中×1 + 缓存读×0.1 + 缓存写×1.25 + 输出×4`。相对权重，把四种桶揉成一个可比的量。
- **有效 / 无效 / 未表态**：按**人工标注的轮次**归类。有效 = 用户接受了这一轮；无效 = 要求重做或换目标；未表态 = 没有可判读的表态。**未标注的会话只显示结构口径，不拿估算冒充标注。**
- **六分量**：`ASSISTANT_ECHO` / `TOOL_RESULT` / `TOOL_SCHEMA` / `PREFIX_SYSTEM` / `USER_TURN` / `COMPACTION`。分量归属是字符权重分摊（可加总守恒），总量始终来自 provider 上报的 usage。
- **缓存**：`prompt = 命中 + 本该命中却漏 + 新增`，只把最早的分叉归因，避免重复计数。

## 标注器

插件不自带任何标注数据——**效费比需要你自己标**，否则只显示结构口径。

洞察页有「标注队列」：自动从会话里抽未标注的轮次（每会话最多 2 条，按 ET 降序），
每行显示 `会话名#轮次` + 用户下一句，点四个按钮之一即存：

| 按钮 | 含义 |
|---|---|
| 接受 | 用户往下走 / 开新任务 / 明确认可 |
| 返工 | 目标没变，但要求修 / 重做 / 删 / 改 |
| 换目标 | 用户改了要的东西本身 |
| 未表态 | 无后续、系统消息、纯流程噪音 |

旁边的 **「标注手册」** 按钮打开固定基准（边界三步 + 11 条特殊情形 + 例子），
用来消除标注漂移。

标注存在**安装了本插件的 profile 目录**下的 `token-effi/labels.json`，不写插件包、不写你的源码；
面板底部常驻显示完整路径。

## 局限

- 标注是**抽样**的：一个会话只有部分轮次被标注，效费比是这些轮次的合计，面板会标出覆盖轮数。
- 分量归属是 `aligned` 级精度（字符权重分摊），不是 provider 的 tokenizer。
- 缓存归因里 `provider_side` 与 `block_granularity` 属噪声底，不要当漏点读。
- 只读：不修改会话、不发起模型调用。
