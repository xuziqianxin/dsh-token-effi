# dsh-token-effi

> DeepSeek Harness 插件：**按会话算效费比**——这笔会话花的钱，有多少变成了你要的东西。

大部分 token 统计告诉你"花了多少"，这个插件回答"值不值"。

- **效费比**：有效产出 vs 返工，各占多少钱、各占多少 token
- **钱花在哪**：输入侧六分量、缓存命中与漏点、输出分块
- **标注工作流**：内置标注器 + 固定判准手册，避免口径漂移

安装后左侧导航多一项 **效费比洞察**，会话顶部叶签多一项 **效费比**。

---

## 安装

### 前置

- DeepSeek Harness `>= 0.2.0-rc.2`（桌面版或 web 版均可）
- Node `^22.19.0 || >= 24.0.0`

插件是纯 JS，**无需构建、无需额外依赖**。

### 方式一：Add plugin（推荐）

1. 打开 **Plugins** 页面，点 **Add plugin**
2. 在搜索框里填包名 `dsh-token-effi`，点 **Install**
3. 安装完成后**刷新页面**（Ctrl+F5）

> npm 包发布前，方式一找不到。先用方式二或三。

### 方式二：本地目录

1. 把本仓库 clone 或下载到本地任意目录
2. **Plugins → Add plugin → 选择目录**，指向仓库根目录（含 `package.json` 的那一层）
3. 刷新页面

这种方式是软链接安装，**改代码即时生效**（Host 侧需要禁用→启用一次插件重载）。

### 方式三：CLI

```bash
# 发布到 npm 后
dsh plugin --profile web add dsh-token-effi

# 更新
dsh plugin --profile web update dsh-token-effi@latest
```

### 验证装好了

1. 刷新页面后，左侧导航出现 **效费比洞察**（柱状图图标，排在"上下文洞察"旁边）
2. 打开任意会话，顶部叶签出现 **效费比**
3. 点开洞察页，几秒内出现 KPI 数字条和会话列表

看不到的话：**Plugins** 里确认 `dsh-token-effi` 这一行是启用状态；改过代码则禁用再启用一次。

### 装不上 / 装完看不到？

**`ERR_PNPM_EPERM rename ... dsh-token-effi`**

同名包还在 `node_modules` 里（旧版本、或开发模式的软链接）。按顺序做：

1. 卸载：**Plugins** 里移除 `dsh-token-effi`
2. 完全退出 DSH（不是关窗口，是退出进程）
3. 删掉残留目录：`cmd /c rmdir "C:\Users\<你>\.dsh\profiles\<profile>\node_modules\dsh-token-effi"`
4. 重开 DSH，再装

根因：pnpm 要把新目录 rename 到旧目录上，而旧目录是正在被进程占用的软链接。

**装完没有「效费比洞察」**

- 先 **Ctrl+F5** 硬刷新（客户端 bundle 需要重新加载）
- 确认 **Plugins** 里这一行是启用状态
- 用了非标准 profile 的话，确认里面有 `@deepseek-ai/dsh-client-ui-conversation`（客户端半边依赖它）

**面板一直在转圈 / 报「分析失败」**

看红字提示。常见是标注文件写不进去：`<profile>/token-effi/labels.json` 所在目录无写权限。

**「结构口径」但算不出效费比**

正常，还没标注。去标注队列标几轮。

### 兼容性

- 只在 **DSH `0.2.2-rc.3`**（Windows 桌面版）上验证过
- 没有运行时依赖，宿主侧只用 Node 内置模块
- 用到了 `sessionQuery`、`connection.fetch`、`main`/`sidebar.panellist`/`conversation.view` 三个槽——更老的 DSH 版本可能没有

### 卸载

**Plugins** 里对该插件点移除。标注数据不在插件包内，卸载不会删除（见下方「数据存在哪」）。

## 使用教程

### 0. 第一次打开：先知道会看到什么

插件**不自带任何标注数据**。第一次打开效费比区块会显示"未标注 · 只能看结构口径"——这是设计，不是坏了。

要看到真正的效费比，先标 10–20 轮（第 3 节），大约五分钟。

### 1. 两个入口

| 入口 | 位置 | 看什么 |
|---|---|---|
| **效费比**（叶签） | 会话里 Chat / Trajectory / Context 旁边 | **只看当前打开的这个会话**，切会话自动跟随 |
| **效费比洞察**（整页） | 左侧导航栏 | 一屏看范围内所有会话，点一行看明细 |

### 2. 读洞察页

```
效费比洞察                                             [刷新]
范围  [近 7 天] 近 30 天  近 1 年  全部              分析中 9/16
✦ 输出 token 通常只占总量的 0.3%，却能吃掉三成成本……

┌ 会话数 ┐┌ 总 ET ┐┌ 有效占比 ┐┌ 有效:无效 ┐┌ 已标注轮 ┐
│  16    ││ 1.2B  ││  29.3%  ││ 1 : 3.23 ││   203   │

┌ ☰ 会话窗口 ─────────────────────────────────────────┐
│ ● Python 游戏存档修改器  20 轮  34.33M  ████░░░░  12.5% │
│ ● QuizForge 答题系统     71 轮  120.3M  ███░░░░░  —
└──────────────────────────────────────────────────────┘

（选中行的明细：效费比环形图 / 钱花在哪 / 缓存 / 输出分块 / 最贵轮次）
```

**范围选择**：默认只算**最近 7 天有活动**的会话（活动时间取会话目录里最新文件的 mtime），避免一上来算几十个会话。切范围立即重算，不用再点刷新。

**几个数的意思**：

| 数字 | 含义 |
|---|---|
| 效费比 | 有效产出的钱 ÷ 总钱。20% 意味着五分之四的投入没变成你要的东西 |
| 有效 : 无效 | 1 : 3.23 = 每 1 块钱有效，配 3.23 块钱返工 |
| 有效 token 占比 | 同上，但按原始 token 数算。和按钱的口径接近，说明结论不依赖价格假设 |
| 单位有效产出成本 | 总 ET ÷ 有效轮次。越小越好，可跨会话比较 |
| ET | 等效 token：`未命中×1 + 缓存读×0.1 + 缓存写×1.25 + 输出×4` |

### 3. 标注（关键一步）

洞察页有一张 **标注队列** 卡片：自动从会话里抽**未标注**的轮次（每会话最多 2 条，按 ET 降序，一次 12 条）。

每行显示：

```
Python 游戏存档修改器#10                删掉增加的提示内容保留文字UI…
4.67M ET                               [接受] [返工] [换目标] [未表态]
```

**只看「用户下一句」**，点一个按钮即存。存完立刻重算该会话，那一行自动消失、下一条补上来。

队列固定 12 条，标一条补一条是正常的——要看进度请盯 **「已标 N 轮」** 这个数。

四个按钮的含义：

| 按钮 | 什么时候点 |
|---|---|
| **接受** | 用户往下走 / 开新任务 / 明确认可（对、好、继续、就这么定） |
| **返工** | 目标没变，但要求修 / 重做 / 删 / 改 / 重写 |
| **换目标** | 用户改了要的东西本身（换方案、加范围、推翻需求） |
| **未表态** | 无后续、系统消息、纯流程噪音 |

拿不准时点右上角 **标注手册**（悬浮窗，Esc 关闭）——里面是固定基准：边界三步、11 条特殊情形（会话第一轮怎么标、一轮做了几件事怎么标、只问用法算不算接受……）、三个例子。

### 4. 看完数之后

按杠杆排序，值得先做的通常是：

1. **返工占比高** → 看「最贵的轮次」里被退回的那几条，通常是同一类问题反复出现（修不干净、漏功能、形式返工）
2. **单位有效产出成本高** → 看「步 / 轮」，步数越多，每一轮都在重发整份上下文
3. **缓存漏点多** → 看漏点归因，`tools_changed` / `param_changed` 每次会作废整段前缀

## 口径

- **ET（等效 token）**：`未命中×1 + 缓存读×0.1 + 缓存写×1.25 + 输出×4`。相对权重，把四种桶揉成一个可比的量。
- **有效 / 无效 / 未表态**：按**人工标注的轮次**归类。未标注的会话只显示结构口径，**不拿估算冒充标注**。
- **六分量**：`ASSISTANT_ECHO` / `TOOL_RESULT` / `TOOL_SCHEMA` / `PREFIX_SYSTEM` / `USER_TURN` / `COMPACTION`。分量归属是字符权重分摊（可加总守恒），总量始终来自 provider 上报的 usage。
- **缓存**：`prompt = 命中 + 本该命中却漏 + 新增`，只把最早的分叉归因，避免重复计数。

## 数据存在哪

按 DSH 官方约定，用户数据放在 `$DSH_HOME/<子系统>/` 下（与 `dsh-office-kit` 的
`dshHomePath('office-kit', 'outputs')` 同构）：

```
$DSH_HOME/token-effi/labels.json          # 默认 ~/.dsh/token-effi/labels.json
```

不写插件包、不写源码目录，也不会跟着 profile 走。`$DSH_HOME` 自定义时自动跟随。
面板底部常驻显示完整路径。插件更新或重装不会动这个文件。

老版本（`<= 0.1.1`，存在 `<profile>/token-effi/` 或包内 `data/`）会在首次启动时**自动迁移**过来。

## 常见问题

**打开效费比区块是空的 / 只显示"结构口径"？**
还没有标注。去洞察页的标注队列标几轮。

**洞察页列表是空的？**
范围太窄。切到「全部」看看。

**数字和别的工具对不上？**
口径不同。这里的分母是"计费 token 折算的钱"，不是 token 数；输出通常只占 token 总量的很小一部分，却占相当一部分成本。

**会不会上传我的数据？**
不会。插件只读本地会话日志，标注写本地文件，不发任何网络请求。

## 局限

- 标注是**抽样**的：一个会话只有部分轮次被标注，效费比是这些轮次的合计，面板会标出覆盖轮数。
- 分量归属是 `aligned` 级精度（字符权重分摊），不是 provider 的 tokenizer。
- 缓存归因里 `provider_side` 与 `block_granularity` 属噪声底，不要当漏点读。
