# 效费比

回答两个问题：**这笔会话的钱，有多少变成了你要的东西；有效和无效 token 各占多少。**

插件给两个位置：

## 1. 会话叶签「效费比」

在 Chat / Trajectory / Context / Fleet 后面多一个叶签，**只统计当前打开的这个会话**，
切换会话时面板跟着换。不扫描、不预计算其它会话。

## 2. 左侧「效费比洞察」页

点左侧导航里的柱状图图标打开，一屏看**所有会话**：

| 区块 | 内容 |
|---|---|
| 顶部数字条 | 会话数 / 总 ET / 有效占比（按已标注会话加权）/ 有效 : 无效 / 已标注轮 / 有标注的会话 |
| 会话窗口列表 | 按 ET 降序，每行一条占比条 + 效费比；点一行在下方展开明细 |
| 标注队列 | 自动抽未标注的轮次（每会话最多 2 条、按 ET 降序、一次 12 条）；点一个按钮即存 |
| 明细 | 与叶签相同的四张卡 + 最贵的轮次 |

### 标注手册

标注队列上方有「标注手册」按钮，点开是一个悬浮面板（Esc 关闭），把口径钉死：

- 判什么：只看「用户下一句」，不看产出好坏
- 四类定义
- 边界三步：有没有人话 → 新的事还是这件事 → 目标变没变
- 特殊情形：会话第一轮、一轮做了几件事、只问怎么用、重复说同一件事、系统消息、报错中断、讨论里反驳论断…
- 三个例子
- 减少漂移的做法（连标 10–15 条、拿不准先记 note、每 10 条自检）

标注写入 **`$DSH_HOME/token-effi/labels.json`**（默认 `~/.dsh/token-effi/labels.json`），
遵循 DSH 官方约定：用户数据放在 harness home 下的子系统目录，通过运行时注册的
`dshHomePath` 解析，`$DSH_HOME` 变化时自动跟随。面板底部常驻显示该文件的完整路径。
老版本放在 `<profile>/token-effi/` 或包内 `data/` 的标注会在激活时自动迁移。

打开时默认只统计**最近 7 天有活动**的会话（活动时间取会话目录里最新文件的 mtime，不解析日志），
顶部有 近 7 天 / 近 30 天 / 近 1 年 / 全部 四档范围。分析按 3 并发进行，加载期间轮播研究速览。

## 指标

| 区块 | 内容 |
|---|---|
| 顶部数字条 | 轮次 / 请求 / 步每轮 / 总 ET / prompt token / 已标注轮 |
| 效费比 | 环形图（有效 / 无效 / 未表态）+ **有效 token 占比（按量）**、有效 : 无效、单位有效产出成本 |
| 钱花在哪 | 输入侧六分量：`ASSISTANT_ECHO` `TOOL_RESULT` `TOOL_SCHEMA` `PREFIX_SYSTEM` `USER_TURN` `COMPACTION` |
| 缓存 | 命中 / 本该命中却漏 / 新增，附漏点归因 |
| 输出分块 | 正文 / 工具参数 / reasoning 的比例 |
| 最贵的轮次 | 按 ET 降序，带人工标签与用户的下一句 |

两个口径同时给：**按钱**是 ET 加权（`miss×1 + hit×0.1 + write×1.25 + out×4`），
**按量**是原始 token 计数。两者接近时说明结论不依赖价格假设。

## 口径

- **ET**：`miss×1 + hit×0.1 + write×1.25 + out×4`，相对权重，用来把四种 token 桶揉成一个可比的量。
- **有效** = 该轮用户接受了（接着往下走）；**无效** = 要求重做或换目标；**未判定** = 会话结束/没有表态，单列不摊。
- **缓存**：`prompt = 命中 + 本该命中却漏 + 新增`，只把最早的分叉归因，避免重复计数。

## 标注表

面板里的「有效/无效」依赖轮次标签，来自包内的 `labels.json`，键是 `会话前 8 位#轮次`。
只有被标注过的轮次才算得进效费比；没有标注的会话只显示结构口径（正常结束率与旧 CoP），
不会拿估算冒充标注。

## 局限

- 标签是**抽样的**：一个会话只有部分轮次被标注，效费比是这些轮次的合计，面板会标出覆盖轮数。
- 字符权重不是 provider 的 tokenizer，分量归属是 `aligned` 级精度；总量始终来自 provider 上报的 usage。
- 缓存归因里 `provider_side` 与 `block_granularity` 属噪声底，不要当漏点读。
- 只读：不修改会话、不发起模型调用、不写任何文件。
